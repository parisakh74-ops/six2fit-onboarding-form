## 3. Which variant fits

- **Background:** the header sits on `bg-surface` (`oklch(0.969 …)`, near-white) and the cards on white. A dark theme is defined in CSS (`.dark`) but nothing in the app enables it. → **Black** variants. White variants only if a dark theme is ever switched on.
- **Logo or logotype for the header:** the image is rendered 24–28 px high with `alt="6toFit"`. The wordmark (3.74 : 1) becomes about 90–105 px wide and reads as the brand name; the mark alone would be a 16–19 px "6". → **`6toFit_logotype_Black_1`**. (The removed original cannot be inspected; its size, 16,854 B, does not decide this. PM to confirm.)
- **Favicon source:** the mark (`6toFit_logo_*`). A black mark on a transparent background is invisible in dark browser tab bars and the white one in light tab bars, and no square, background-filled favicon artwork exists. Recommendation: use the official `6toFit_logo_Black_1.svg` (vector) with `6toFit_logo_Black_1.png` as fallback only if the PM accepts the dark-tab limitation; otherwise the PM supplies a dedicated square favicon. Do not redraw, recolor or crop.

## 6. Expected output and publishing implications

- Vite emits hashed files under `.output/public/assets/`, for example `6toFit_logotype_Black_1-<hash>.svg` (the 4,114 B SVG is just above Vite's 4,096 B inline limit, so it should be a file; verify in the build).
- The existing step "copy `.output/public/assets` into the Document Root `assets/`" (additive, SHETABANHOST SOP D.4) publishes them; no new root-level file or hosting change is needed.
- `<link rel="preload" as="image">` and `<link rel="icon">` in the HTML point to the hashed URLs (the preload does not disappear).
- Verify after a future deployment: both URLs return 200, the content type is `image/svg+xml` (**[U]** not yet verified on this host for `.svg`), and the served file is byte-identical to the source file.

**Correction after the first test run:** the favicon mark (1,814 B) is below Vite's 4,096 B inline limit, so it is embedded in the HTML head as a `data:image/svg+xml,…` URI and produces no separate file; only the logotype (4,114 B) is emitted as a hashed file under `assets/`.
